# ADR-0001: Cordis вместо NestJS в роли application composition

- **Дата:** 2026-11-11
- **Статус:** proposed / требуется технический spike
- **Решение:** TypeScript/Node.js, самостоятельный модульный монолит; Cordis — для управляемого подключения сервисов, зависимостей и адаптеров. Не тащить DSH или его AI-функции.

## Контекст
Платформа должна добавлять виды отчётов и адресатов в конфигурации, а новые типы источников/документов/оповещений — как код-плагины. Позже интеграция с Pulse. Классический NestJS удобен для HTTP/DI, Cordis ближе к DSH-подобной модели plugin composition.

## Принципы выбора
- Основной язык: **TypeScript**, интерфейс: **React**.
- Cordis не является ORM, HTTP-сервером, планировщиком задач или BPMN engine.
- Сохраняем модульный монолит, инфраструктурные adapters и строгие контракты.
- Корпоративная безопасность требует approve+pin версий кода-плагинов.

## Что проверить перед «accepted»
1. Совместимость текущей точной версии `cordis` c Node 22+, ESM, жизненным циклом и runtime shutdown.
2. Регистрация HTTP/Fastify-адаптера и взаимных зависимостей 3–4 плагинов.
3. Поведение при падении плагина, обновлении конфигурации, остановке во время обработки задачи.
4. Управление DB pool и транзакциями без нарушения целостности данных.
5. Удобство модульного тестирования сервисов без runtime.
6. Возможность безопасного изолированного запуска worker и API на одном наборе доменных модулей.
7. Совместимость лицензий, доступность фиксируемой версии и поддерживаемость разработчиками.

## Альтернативы
- NestJS: более предсказуемый enterprise-каркас, меньше рисков интеграции, но сложнее модель plug-in runtime.
- Fastify + собственный DI: минимально, но реализовать весь жизненный цикл и сервисные зависимости придётся самим.
- DSH: не подходит как база регламентированной отчётности, предназначен для AI-агентов.

## Обратимость
Все бизнес-методы размещать за интерфейсами `ports`. Ни доменные сущности, ни API DTO не должны импортировать Cordis. Если spike не пройдёт, адаптер runtime заменяем на NestJS без миграции доменной модели. **До принятия ADR — не писать десятки production-плагинов.**
