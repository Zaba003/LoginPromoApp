# 06. Безопасность, эксплуатация и достоверность

- **Закрытый контур по умолчанию:** никакой зависимости от облачных API, CDN, телеметрии, удалённых маркетплейсов плагинов.
- **RBAC + ABAC:** `module:action` и ограничения по организации/подразделению/отчёту/периоду/статусу. Правила проверяются на сервере.
- **Плагины как доверенный код:** подписанный/проверенный комплект поставки, allowlist, pin версий; hot-reload не считается security sandbox.
- **Audit trail:** кто создал/изменил/сдал/согласовал данные, какая версия была показана/утверждена; append-only + защита журналов.
- **Provenance:** для каждого сводного значения доступны исходные формы, утверждённые версии, формулы и методики.
- **Резервное копирование:** восстановление БД и файлов единым согласованным снимком; проверка восстановления.
- **Документы:** контрольная сумма, версия шаблона, состояние утверждения; антивирусный контроль входящих файлов и ограничения типов/размеров.
- **Доступность:** очередь задач переживает рестарт; повторный запуск идемпотентен; дедлайны рассчитываются в согласованной временной зоне.
- **Секреты:** не хранить пароли, ключи и токены в YAML конфигурациях или Git; использовать защищённое локальное хранилище секретов.
- **ЭП/регуляторы:** конкретные нормы, юридически значимое подписание, место хранения и каналы сдачи разрабатываются отдельно под реальные требования получателей; нельзя обещать правовое соответствие заранее.

## Критические тесты
1. Руководитель отдела А не видит черновик отдела Б без полномочий.
2. После утверждения форма и значения не меняются незаметно.
3. Перерасчёт с зафиксированными входами детерминирован и воспроизводим.
4. Смена версии отчёта не меняет архивный отчёт.
5. Повторно доставленное событие не дублирует задание или итоговый документ.
6. При отключённом Pulse система продолжает работать.
