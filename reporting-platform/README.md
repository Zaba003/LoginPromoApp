# Платформа отчётности — Reporting Platform

**Статус:** архитектурный starter / прототип (не промышленная система).  
**Дата фиксации концепции:** 11.11.2026.  
**Идея:** самостоятельная on-prem платформа регламентированной и внутренней отчётности научной организации; в перспективе — интеграция с Pulse.

## Задача

Руководители и ответственные сотрудники подразделений получают задания на отчётность по расписанию, заполняют динамические формы, согласовывают данные. На основании согласованных сведений система формирует один или несколько итоговых отчётов для **разных получателей**, сохраняя происхождение показателей и версии регламентов.

Не путать **показатель**, **форму ввода**, **сдачу отчёта**, **отчётную кампанию**, **сводный документ**. Они живут и версионируются отдельно.

## Предлагаемый стек

- **TypeScript** сквозной для фронтенда, бэкенда и контрактов.
- **Cordis** — композиция модулей бэкенда (решение для технического spike, см. ADR-0001). Не использовать DSH как приложение.
- **Node.js 22+**, HTTP-адаптер на выбор после spike (предпочтительно Fastify), **React + Vite** для UI.
- **PostgreSQL** — системный источник истины, транзакции, связи, аудит; `JSONB` — для значений по версионированным схемам, не вместо нормализованных сущностей.
- **Kysely + миграции** (предварительно) либо Drizzle по результатам spike; без беспорядочного прямого SQL из плагинов.
- **JSON Schema + JSON Forms** — рендеринг пользовательских форм; **свой конструктор метаданных** как отдельный этап.
- **pg-boss** — долговременная очередь и расписания на PostgreSQL, без обязательного Redis.
- **ExcelJS, DOCX-шаблоны, PDF-экспорт через отдельные адаптеры** — уточнить необходимые форматы и лицензии.
- **OIDC / LDAP через адаптер**, локальная авторизация для автономной работы — по утверждённой модели угроз.
- **REST/OpenAPI, события/outbox** — будущая интеграция с Pulse.

## Структура

```
apps/api/                 # минимальный экспериментальный Cordis runtime с /health
apps/web/                 # запланированный React-клиент (пока документация)
packages/contracts/       # стабильные JSON-контракты и схемы
examples/                 # пример формы и правил формирования отчёта
docs/                     # концепция, архитектура, решения, требования, план
```

## Ключевой архитектурный принцип

**Модульный монолит с plugin runtime.** Cordis управляет сервисами и жизненным циклом адаптеров, но **не** превращает каждую таблицу и каждую бизнес-транзакцию в динамически выгружаемый плагин. Все изменения утверждённой отчётности должны фиксироваться в БД и аудите; запуск плагинов должен происходить из доверенного реестра.

## Что уже готово

Документы концепции, модель, ADR, реестр модулей, минимальный API-стартер, примеры спецификаций. **Реальной платформы, интерфейса форм, БД и механизма отчётности пока нет.** Для запуска нужен npm install и проверка совместимости пакетов; окружение и БД не развёрнуты.

### Экспериментальный запуск API

```bash
npm install
npm run dev:api
# GET http://127.0.0.1:3100/health
```

Эти команды — инструкция к стартовому репозиторию; запуск и установка зависимостей в этом пакете не подтверждены. Если API Cordis изменится, поправить spike, а не доменную модель.

## Порядок работы

1. Прочитать `docs/01-vision.md`, `docs/02-architecture.md`, `docs/adr/0001-cordis.md`.
2. Выполнить технологический spike: Cordis + HTTP + PostgreSQL + 2 зависимых плагина + graceful shutdown.
3. Описать первый реальный образец формы/показателя и правила консолидации.
4. Разработать минимальный вертикальный сценарий: шаблон → кампания → задача → данные → проверка → сводный экспорт.
5. Подключать сложный BPMN/DMN только после подтверждения необходимости.

**Нельзя считать это готовым ТЗ или production-ready проектом:** юридически значимая отчётность, хранение, ЭП и регуляторные требования уточняются отдельно.
